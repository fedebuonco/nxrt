## What this work is

nxrt is the shared runtime for Switch static recompilations: the game code is generated by `tools/gen.py` from the
player's own NSOs, compiled into `<id>game.dylib`, and nxrt provides everything around it (kernel, HLE services,
NVN → Metal/Vulkan, input, saves, settings, start screen).

LASRecomp's `beta_5` has ~26,000 lines of runtime work nxrt lacks. We are porting it into nxrt — **not** rebasing
LAS onto nxrt — so that every game built on nxrt gets it. Three ports drive the work: `games/las`, `games/eow`,
`games/sky` (not committed; they hold the owner's game files and their own patches).

Branches: **`beta5-merge`** (the merge of the rest of beta_5) and **`nvn-renderer-wip`** (beta_5's renderer, with
`beta5-merge` merged into it); both are merged into **`master`** now (`v0.2.0`).

## The rule this port keeps teaching us

Every failure so far was **beta_5 code that still says "LAS" where the library must be game-agnostic**. Ten of them,
each found by running a real game:

| Bug | Where |
|---|---|
| `hle/libc.c` missing | new file never imported → libraries didn't load at all |
| `library_name()` accepted only `lasgame.*` | `build_cache.cpp` → "Invalid game library filename." |
| builder generated only `main` + `sdk@7004000000` | `gamebuild.c` → `no function at 700c100620` |
| library's module table came from `NX_MODULES`'s fallback | `gamelib_entry.c`, never passed by the builder |
| cache identity ignored the module layout | `build_cache.cpp` → stale code reused |
| cache's module list was `main`/`sdk` only | `build_cache.cpp` → "Invalid generated module." |
| package RomFS (`romfs.src`) not supported | `services/fs.c` → "cannot read the game data" |
| merged `kernel.c` deadlocks in `ArbitrateLock` | reverted to nxrt's; beta_5's kernel still unported |
| Delete dialog activated itself | `rt_ui.mm` (ImGui focuses the button as the popup opens) |
| `lasrecomp` strings | temp dir, comments (the `.lasrecomp_*` move markers stay: they recover interrupted moves) |

**Before porting any beta_5 file, grep it for `las`, `LAS_`, `LARECOMP_`, and hard-coded module names.** Expect more.

## The renderer: why this is the hard part

beta_5's `metal.m` / `renderer.m` are not "our renderer with extras". They contain **no game interface at all**:

```
NX_HOOK calls in beta_5's runtime/nvn:
  tex_identify 4 · tex_generation 4 · tex_apply 4
  draw_shader 0 · draw_textures 0 · draw_tint 0 · draw_mirror 0 · instances_tinted 0
```

LAS's own calls were inlined instead (`texpatch_*`, `recolour_*`, `escape_bottle_tint`, `pot_tint`, `hint_sheet_*`).
Importing the files as-is deletes the interface every game depends on.

### What has already been done (parked branch `nvn-renderer-wip`, commit `33c13c0`)

- beta_5's whole `runtime/nvn/` imported (metal, renderer, objects, output_scale, pace, rqueue, slowframe,
  shader_prep/seen, tex_hash, skin_face, screen_filter, vulkan/{record,shaders,vma}).
- `NxDraw g_draw` filled per draw; `draw_shader`, `draw_textures`, `draw_tint`, `draw_mirror` re-inserted;
  `tex_identify`/`tex_generation`/`tex_apply` restored (they are **1:1 renames**: `texpatch_marker`,
  `texpatch_generation`, `texpatch_apply`).
- New hook `tex_replace(id)` for "draw this game icon in place of that texture" (the Hint Sheet).
- LAS-only calls removed or mapped: `widescreen_*` → `present_*`, `pot_*`/`recolour_*`/bottle/heart dropped
  (`draw_tint` covers them), `warp_frame`/`save_editor_frame` dropped.
- `settings_resolve_defaults`, `screen_filter`/`fullscreen`/`bg_input` added.

**Resolved: the branch was 15 commits behind, and the start screen had no Metal layer.** Two separate hangs:

1. `nvn-renderer-wip` predated `hle/libc.c`, the package RomFS, the module-list fixes and the kernel revert. A game
   library built against it could not even load (`_hle_bcmp` unresolved). Merged `beta5-merge` into it.
2. beta_5's `ui_window_init` dropped `nxui_metal_setup(...)`, so the start screen's backend had a nil layer:
   `frame_begin` returned NULL every frame and the launcher spun in `SDL_Delay(16)`. Restored.

The render queue was never the problem: `rq_on()` starts the render thread lazily (`pthread_once`), and
`backend_init()` is called from `nvnDeviceInitialize`. With the merge in, LAS boots and holds 60 fps on beta_5's
renderer; the title, file select and intro all render correctly.

### Translator: one translator, and why it is beta5-merge's line

**Decision reversed by evidence.** beta_5's translator cannot run EoW: its world shaders use BREV, FLO.SH and
HSETP2 immediates, which beta_5's translator does not implement. It failed them (`FS translate failed: bfe brev`,
`unknown instruction 50d9…`) and skipped the draws, leaving EoW's HUD over a black world. `beta5-merge`'s
translator was built for exactly that game.

So `nvn-renderer-wip` now uses **`beta5-merge`'s translator**, with beta_5's one game-visible addition ported on top:
the Metal sampler map for fragment shaders with more than 16 textures (issue #215, the Ukuku cave-floor shader:
samplers as an array, a table naming each texture's slot; `renderer.m` already had the renderer side). `shader.h`
keeps the superset (`alpha_func`/`dual_source`, the Metal sampler constants, `ssbo_read` for the Vulkan backend).

Evidence: LAS 0 translate failures at 59.9 fps, EoW's world renders with 0 skipped draws. One EoW compute shader
still fails (`eb20138600f70018`), and Sky is untested since this swap.

What beta_5's translator still has that this one does not, if we want it for every port:

- **Cosmetics recolour** (`emit_recolour_window`, `ltint[4]`, HSV windows). Currently unreachable: `draw_tint` hands
  the renderer 8 floats (two vec4) and the recolour needs all four. Porting it means widening the hook to 16 floats
  and restoring `recolour.c`'s caller.
- **Vulkan chunked heap** (`maxwell_gmem_chunk_shift`/`lazy`: windows or buffer references instead of one buffer for
  the whole heap; the AMD/Intel path). The Vulkan backend still reads the controls, but this translator binds the
  whole heap as one buffer. Vulkan-only, testable only where Vulkan runs.

### What the interface still needed

The import claimed the hooks were back; `draw_tint`, `instance_tint` and `instances_tinted` were **not called**
(the tint buffer was zero-filled, the per-instance runs dropped). Restored from `beta5-merge`'s renderer, with
`NXRT_LOG_HOOKS=1` logging the first call of each so "no hooks" cannot pass silently. The window title is
`nx_game.info.title` again in both backends.

### Next, in order

1. **EoW in game** (Metal): done past the first 3D scene (opening dungeon, 60 fps). What is left is a longer play
   session (combat, menus, save/load) and the one untranslated compute shader (`eb20138600f70018`).
2. **LAS in a dungeon**: pots/items (draw_tint, instance_tint) and the Hint Sheet icon (`tex_replace`), against
   beta5-merge's renderer. `draw_tint` is confirmed called in the field; the item/pot visuals are not yet compared.
3. **Vulkan**: the same interface audit in `vulkan/exec.c` + `record.c`, on a machine where it runs.
4. Then the rest of beta_5's `kernel.c` (the merge deadlocks EoW — see `e481c2a`; port it with the EoW boot as the

5. Framerate is *not* a reason for this work any more: LAS and EoW already run at a locked 60 fps on nxrt's renderer

## Sky's stall (fixed)

It was **not** `WaitProcessWideKey` and not `ArbitrateLock`. The 0x1C threads in the profile are ordinary condition
variable waits (the dump showed `wait=2`, mutex word 0). The chain was:

1. `ISelfController` command 9 (`GetLibraryAppletLaunchableEvent`) was created **unsignaled**, so after ~31 frames
   Sky waited forever before opening its first library applet. It is signaled now (`runtime/services/am.c`).
2. `ILibraryAppletCreator::CreateLibraryApplet` returned nothing, so the SDK asserted (no free applet slot). Library
   applets now exist: an `ILibraryAppletAccessor` that reports started/completed at once, and `IStorage` for the
   applet's data (`runtime/services/am.c`). That is shared and helps any game that opens a system dialog.
3. Sky still stopped inside `ShowControllerSupportCore` right after the applet was created. The console's
   "attach the Joy-Con straps" dialog has no meaning in a desktop port, so **Sky's port** replaces that one SDK
   function with a no-op: `nn::hid::ShowControllerStrapGuide` at `0x7030244c80` (this SDK build), via
   `hle_override` from its `modules_loaded` hook (`games/sky/runtime/sky_game.c`, not committed: the ports are
   the owner's). The runtime mechanism is shared; the address belongs to the port.

With that, Sky plays at 60 fps. Known: ~240 draws a frame skipped (one fragment shader fails with "bindless tex"),
and the crash dialog no longer claims files are missing (the old LAS count is gone).

Two renderer crashes on the way there were real and are fixed: an uninitialized present `crop` (MetalFX set up for
16384×16384, then a zero-size texture) and a clear kind read from an argument the recorder never set for float clears
(Sky's was 15). `SetRenderTargets` and `clear_lib` also index 8-entry arrays with an unclamped guest value.

Reproduce (the app is built into `build-wip` so the `beta5-merge` build stays usable):

```zsh
cd games/sky && NXRT_SETTINGS=/tmp/skydata/skyrecomp.ini NXRT_DATA_ROOT=/tmp/skydata \
  NXRT_WINDOW=960x540 NXRT_HANG_DUMP=10 timeout 60 ./build-wip/skyrecomp --play
```

## Environment and how to verify

```zsh
# build one port (macOS, ~1 min for the app; the game library is separate)
cd games/las && export SDKROOT=$(xcrun --show-sdk-path) && make -j10 CLANG=/usr/bin/clang

# the start screen alone, no game files needed, screenshotted
cd examples/game-template
NXRT_DATA_ROOT=/tmp/x NXRT_LAUNCHER_SHOT=25 NXRT_SHOT_PATH=/tmp/x.png ./build/templaterecomp

# a port against its real files, without touching the owner's data folder: the settings file is
# <port>.ini in the data root (not "port.ini"), and the app reads it through NXRT_SETTINGS
printf 'game_dir = <game folder>\ngame_in_place = 1\n' > /tmp/d/larecomp.ini
NXRT_SETTINGS=/tmp/d/larecomp.ini NXRT_DATA_ROOT=/tmp/d ./build/<port>recomp --play   # --play skips the start screen

# A/B switches that already exist
NXRT_ROMFS_BIN=1     # serve from romfs.bin instead of the folder (data-path A/B)
NXRT_BUILD_JOBS=<n>  # fewer parallel compilers (big games exhaust memory)
NXRT_PROF_SVC=1      # per-thread service counters every 2 s
NXRT_DUMP_THREADS=1  # event creation with the creating HLE function
```

Game folders (owner's drive, **read-only for you**):

```
LAS  <your drive>/LA-extract                         (romfs/ folder, 3836 files)
EoW  <your drive>/EoW Recomp game                    (romfs.src package)
Sky  <your drive>/.../Sky Recomp game                (romfs.src package)
```

Rules: never commit game files, keys, generated C, `*.dylib`/`.id`, or saves. Rebuilds of a game's library take
10–15 min; the app alone takes ~1 min, so prefer app-only changes when testing.
